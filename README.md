# WebSocket 语音活动检测与音频片段传输接口文档（最终版）

## 概述

本文档描述了WebSocket语音活动检测系统的接口规范。系统使用固定16000Hz采样率的单声道32位浮点型PCM音频格式（小端序）。服务器在检测到语音活动时发送特殊标记的控制命令，并在语音结束后返回音频片段。

------

## 1. WebSocket连接

- **URL**: `ws://localhost:8765/ws/audio`
- **协议**: WebSocket (ws或wss)
- **连接建立**: 客户端发起连接请求
- **连接保持**: 保持长连接直到客户端主动断开或发生错误
- **认证**: 无需认证
- **配置**: 无需发送配置信息（固定16000Hz采样率，单声道）

------

## 2. 客户端到服务器的消息

### 2.1 音频数据 (二进制格式)

客户端持续发送音频数据流

**数据格式**:

- 32位浮点型PCM数据
- 小端序 (little-endian)
- 单声道
- 采样率: 16000Hz
- 每个样本为32位浮点数（4字节）

**数据块大小**:

- 客户端可自由选择数据块大小
- 建议数据块大小: 512-4096样本（2048-16384字节）

------

## 3. 服务器到客户端的消息

### 3.1 语音活动控制命令 (二进制消息)

服务器在检测到语音活动状态变化时发送特殊标记的控制命令

**语音开始标记**:

- 二进制消息内容: `"<|PAUSE|>"`(UTF-8编码)
- 当服务器检测到语音开始时发送
- 表示语音活动开始，音频处理正在进行

**语音结束标记**:

- 二进制消息内容: `"<|RESUME|>"`(UTF-8编码)
- 当服务器检测到语音结束时发送
- 表示语音活动结束，音频处理完成

### 3.2 音频片段 (二进制格式)

服务器在语音结束后返回录制的音频片段

**数据格式**:

- 32位浮点型PCM数据
- 小端序 (little-endian)
- 单声道
- 采样率: 16000Hz
- 包含从语音开始到语音结束的完整音频片段

------

## 4. 通信流程示例

### 4.1 正常流程

```
客户端 -> 服务器: [音频数据块1] (二进制)
客户端 -> 服务器: [音频数据块2] (二进制)
... (持续发送音频数据)

服务器检测到语音开始:
服务器 -> 客户端: "<|PAUSE|>" (二进制消息)

客户端 -> 服务器: [音频数据块n] (二进制)
... (持续发送音频数据)

服务器检测到语音结束:
服务器 -> 客户端: "<|RESUME|>" (二进制消息)
服务器 -> 客户端: [语音片段] (二进制，包含从语音开始到结束的完整音频数据)
```

### 4.2 说明

- 客户端持续发送音频数据流
- 服务器在检测到语音活动状态变化时发送特殊标记的控制命令
- 语音结束后，服务器返回录制的完整音频片段
- **所有消息都是二进制格式**（包括控制命令）
- 控制命令使用UTF-8编码的特殊标记字符串

------

## 5. 数据格式说明

### 5.1 32位浮点PCM格式

- 每个样本为32位（4字节）浮点数

- 取值范围: -1.0 到 1.0

- 字节序: 小端序 (little-endian)

- 内存布局:

  ```
  Byte 0: LSB (最低有效字节)
  Byte 1: 
  Byte 2: 
  Byte 3: MSB (最高有效字节)
  ```

### 5.2 单声道数据排列

```
[样本1] [样本2] [样本3] ...
```

## 6. 客户端消息处理逻辑

### 6.1 正确识别消息类型

在客户端代码中，需要正确识别不同类型的消息：

```
// 创建WebSocket连接
const socket = new WebSocket('ws://localhost:8765/ws/audio');

// 处理服务器消息
socket.onmessage = (event) => {
    // 所有消息都是二进制格式
    const data = event.data;
    
    if (data instanceof ArrayBuffer) {
        // 将ArrayBuffer转换为字符串以识别控制命令
        const decoder = new TextDecoder('utf-8');
        const text = decoder.decode(data);
        
        if (text === '<|PAUSE|>') {
            console.log('收到语音开始标记');
        } else if (text === '<|RESUME|>') {
            console.log('收到语音结束标记');
        } else {
            // 处理音频片段
            const audioData = new Float32Array(data);
            console.log('收到语音片段，长度:', audioData.length);
            // 处理语音片段...
        }
    }
};
```

### 6.2 发送音频数据

```
// 发送音频数据
function sendAudioData(float32Array) {
    if (socket.readyState === WebSocket.OPEN) {
        socket.send(float32Array.buffer);
    }
}
```

------

## 7. 时序要求

1. 客户端应在连接建立后立即开始发送音频数据
2. 服务器应在检测到语音开始时尽快发送"<|PAUSE|>"命令
3. 服务器应在检测到语音结束后尽快发送"<|RESUME|>"命令和音频片段
4. 音频片段应包含从语音开始到语音结束的完整音频数据

------

## 8. 错误处理

1. 如果连接断开，客户端应尝试重新连接
2. 服务器在发生内部错误时应关闭连接
3. 客户端应处理连接关闭事件并尝试重新连接

------

## 9. 注意事项

1. **所有消息都是二进制格式**，包括控制命令
2. 控制命令使用特殊标记字符串"<|PAUSE|>"和"<|RESUME|>"
3. 客户端需要将二进制消息转换为字符串来识别控制命令
4. 音频片段直接使用Float32Array处理
5. 服务器应确保发送的控制命令是完整的UTF-8字符串

------

## 10. 特殊标记说明

### 10.1 "<|PAUSE|>"

- 表示语音活动开始
- 服务器在检测到语音开始时发送
- 客户端收到此标记后可以暂停其他音频处理（可选）

### 10.2 "<|RESUME|>"

- 表示语音活动结束
- 服务器在检测到语音结束时发送
- 客户端收到此标记后可以恢复其他音频处理（可选）
- 此标记后紧跟语音片段数据
